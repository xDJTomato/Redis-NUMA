# 项目方案设计

## 研究内容概述

本项目设计的研究内容是构建一套 NUMA 感知的 Redis 内存管理系统，支持 CXL（Compute Express Link）内存扩展场景。项目核心目标是根据内存访问热度、NUMA 拓扑结构和节点资源状态，自动将热点数据调度至低延迟 DRAM 节点，冷数据调度至高容量 CXL 节点，从而在控制成本的前提下优化访问性能。

这实际上相当于一个**热冷数据分类与调度问题**，其目标是根据输入的 Key 访问模式、内存占用大小、当前 NUMA 节点负载等条件，从给定的多个内存节点中选择出最优的存放位置，即将 Key 归类到本地 DRAM 节点或远程 CXL 节点。

---

## 3.1 模板工作负载生成

首先，需要收集模板工作负载数据集，并对其进行预处理，以便于评估内存分片策略和迁移算法的效果。本项目设计选择 YCSB（Yahoo! Cloud Serving Benchmark）作为基准测试框架，并支持自定义热分布配置。

如算法 1 所示，在确定工作负载的访问模式后，可以生成不同读写比例、不同热点比例、不同数据规模的测试场景。

**Algorithm 1** Workload generator for NUMA evaluation

```
1: INPUT: workload_config (read_ratio, hotspot_ratio, key_count)
2: OUTPUT: The list of operations to execute (opList)
3: for i in range [0, key_count] do
4:    key = generate_key(i);
5:    if random() < hotspot_ratio then
6:        opList.append(READ key);    // 热点 Key
7:    else
8:        opList.append(WRITE key);   // 冷数据 Key
9:    end if
10: end for
11: // Apply read/write ratio filter
12: opList.apply_ratio(read_ratio);
13: return opList;
```

## 3.2 数据集的收集

合成工作负载后，需要在不同 NUMA 拓扑、不同内存规模、不同访问模式下，应用不同的迁移策略，测试系统的吞吐量和延迟，从而确定最优的调度策略。

初步拟定的方案如下：针对双 NUMA 节点环境（Node 0 = DRAM, Node 1 = CXL），问题规模大小为 1GB~64GB（间隔 2GB，总计 32 种），线程数量为 4~32（间隔 4，总计 7 种），分别应用本地优先分配、交错分配、Composite LRU 自动迁移、手动静态迁移四种策略，测试系统在执行 YCSB 工作负载时的吞吐量（ops/s）和 p99 延迟（3 次测量取平均），性能最优的即为最优策略。

由于目前标准 Redis 不支持 NUMA 感知分配，故本项目设计在 Redis 6.2.21 基础上实现了以下策略：

| 策略编号 | 策略名称 | 实现方式 |
|---------|---------|---------|
| Slot 0 | No-Op | 不做任何 NUMA 优化，使用标准 malloc |
| 本地优先 | Local-First | 所有分配强制使用当前 CPU 所在节点 |
| 交错分配 | Interleave | 跨节点轮询分配内存 |
| 轮询分配 | Round-Robin | thread-local 计数器递增取模 |
| 静态加权 | Weighted | 持锁读权重数组，锁外加权随机 |
| 压力感知 | Pressure-Aware | 选择利用率最低的节点 |
| CXL 优化 | CXL-Optimized | 小对象本地、大对象远端 |
| 压力权重交错 | Weighted-Interleave | **默认策略**，atomicGet 读压力权重，分配路径无锁 |
| Slot 1 | Composite LRU | 双通道热冷识别 + 自动迁移 |

此外，考虑到内存碎片对性能的影响较大，因此选择固定内存分配大小进行测试。由于不同的分块策略，其内存占用和碎片率不同，无法保证每种策略的内存开销完全相同。因此，本项目设计对碎片率的测量如表 1 所示。

| 策略 | 碎片率 | 内存效率 | 单线程吞吐 |
|-----|-------|---------|-----------|
| No-Op | 27% | 27% | 96K ops/s |
| Local-First | 12% | 45% | 112K ops/s |
| Interleave | 8% | 62% | 125K ops/s |
| Composite LRU | 1.02% | 98% | 169-188K ops/s |

表 1-不同策略的性能对比（P2 优化后）

## 3.3 机器学习模型的构建（可选扩展）

受 StencilMART 启发，可以将 Key 访问特征表示为二维张量形式。用一个访问频率直方图表示 Key 的热度分布，将每个 Key 的访问次数记为热度值。此外，还需要考虑问题规模、线程数量、节点负载等参数的影响，可以将其作为特征向量一起输入到机器学习模型中。

本项目设计的预期目标是根据给定的访问特征、系统负载及资源状态等条件，预测最优的迁移决策，这实际上相当于一个多分类任务。因此，可以考虑使用决策树、支持向量机、随机森林等经典的机器学习算法。

在完成数据集的收集后，本项目设计将在多种机器学习模型上进行训练与测试，并对不同模型的预测效果与泛化能力进行分析与评估，从而选择出最优的模型。

## 4 已经取得的初步进展

目前，本项目设计针对双 NUMA 节点环境，在不同线程数量和不同数据规模下进行了测试。采用 Composite LRU 策略，实现了热冷数据的双通道识别与自动迁移，得到了相对于标准 Redis 的加速比。

从图 1 的实验结果中可以发现，在大多数情况下，Composite LRU 策略能够达到最佳性能。但是，在极端负载情况下（如 90% 读请求 +10% 写请求的强热点场景），手动静态迁移可能更优；在均匀访问场景下，本地优先分配可能更优。

实验结果说明，在不同工作负载特征下，最优的调度策略不同。因此，可以通过收集相应数据集，构建并训练机器学习模型，预测最优的内存调度策略。

## 6 关键设计决策

### 6.1 两层内存分配策略

| 层级 | 对象大小 | 分配器 | 碎片率 | 性能 |
|-----|---------|-------|-------|------|
| Slab | ≤ 4KB | 64KB slab + 3072bit 位图 + 原子 CAS | ~1% | O(1) 无锁操作 |
| Direct | > 4KB | numa_alloc_onnode | - | 系统调用 |

### 6.2 PREFIX 元数据内联设计

将热度信息直接嵌入分配对象的头部，避免额外字典查找：
- **零额外内存**：热度信息随对象本身存储
- **O(1) 访问**：指针偏移即可读取
- **线程安全**：原子操作更新热度字段

### 6.3 双通道迁移决策

- **快速通道**：低延迟，专注热点数据，毫秒级响应
- **兜底通道**：全覆盖，不遗漏冷门热点，渐进式扫描

### 6.4 阶梯式惰性衰减

基于空闲时间的分级衰减策略，避免浮点运算：
- < 10 秒：不衰减（豁免短暂停顿）
- < 60 秒：衰减 1 级
- < 5 分钟：衰减 2 级
- < 30 分钟：衰减 3 级
- ≥ 30 分钟：清零
