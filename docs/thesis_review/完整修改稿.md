**修改为（在该段落末尾 [新增] 一段）：**
> 然而，Linux 内核的 Tiered Memory 机制以页粒度（通常 4KB）工作，其 demote/promote 操作由内核的 kswapd 和内存回收路径自动触发，应用层无法直接控制哪些键值被迁移、迁移到哪个节点。对于 Redis 这类键值数据库而言，一个 Redis 对象（robj）可能只占几十字节到几KB，多个对象共享同一物理页；以页为粒度的迁移会导致大量无关对象被连带迁移，产生严重的"碎片化放大"效应。此外，内核 Tiered Memory 的迁移决策基于页面访问位（Accessed Bit），无法利用应用层的业务语义（如热点键识别、热度衰减模型），迁移的精准度远低于用户态方案。这正是本项目选择在用户态实现键值粒度 NUMA 迁移的核心动机。

### 修改17：补充 evict_numa 模块描述（第27–28页之间）

**[新增] 在 3.4.3 节末尾或作为 3.4.4 节之前的独立小节补充：**

> **NUMA 感知淘汰模块（evict_numa）**
>
> 当 Redis 内存占用超过 `maxmemory` 限制时，系统必须执行键值淘汰以释放内存。传统的淘汰策略（如 allkeys-lru、volatile-lfu）仅考虑键值本身的热度信息，在 NUMA 分层内存环境下，这种策略忽略了不同节点间内存容量和压力的差异，可能导致高压力节点被进一步挤占而低压力节点的远端内存未被充分利用。
>
> `evict_numa` 模块在 Redis 原有淘汰流程的候选池筛选阶段介入，为每个候选淘汰键值计算综合评分，选择将其降级（demote）到远端低压力节点而非直接删除。评分公式为：
>
> ```
> score = w_d × distance + w_p × pressure + w_b × bandwidth
> ```
>
> 其中 `distance` 为候选键值当前节点与目标节点间的距离归一化值（权重 40%），`pressure` 为目标节点的内存压力归一化值（权重 30%），`bandwidth` 为目标节点的带宽利用率归一化值（权重 30%）。系统选择评分最高的目标节点执行迁移，若所有目标节点均无法容纳该键值（如远端节点空间不足），则回退到直接淘汰。
>
> 该模块在 `serverCron` 的淘汰流程中被调用，位于 `evictionPoolPop` 之后、实际 `dbAsyncDelete` 之前，作为"先迁移、后删除"的中间步骤。通过这种方式，NUMA 感知淘汰模块能够在不改变 Redis 原有淘汰语义的前提下，最大限度地利用远端内存容量，减少数据的永久丢失。

## 第5章 结论与展望

### 修改26：结论中补充已知限制的诚实表述（第47页，5.1节）

**[新增] 在 5.1 节结论正文之后、5.2 节之前，新增以下段落：**

> 本项目也存在一定限制。QEMU 远端 NUMA 节点只能模拟 CXL Type 3 设备在操作系统层面的资源形态，不能完整模拟真实 CXL 协议栈、链路带宽约束和设备访问延迟。Redis-NUMA 当前的访问统计、策略调度和迁移执行仍运行在 Redis 主线程中，迁移大对象或复杂数据结构时仍可能造成短时阻塞。此外，策略收益与硬件拓扑和业务负载高度相关，在远端节点访问代价较低的环境中，简单 interleaved 分配也可能取得较好效果。

### 修改27：展望中补充两个未来方向（第48页，5.2节）

**[新增] 在 5.2.2 节之后增加新小节：**

> **5.2.3 复杂数据类型迁移完善**
>
> 当前 Redis-NUMA 的键值迁移引擎已实现 STRING、HASH、LIST、SET、ZSET 五种数据类型的适配器，但在实际生产环境中，复杂嵌套结构（如嵌套哈希、大列表）的迁移仍面临挑战。未来工作包括：（1）支持分块增量迁移，将大对象拆分为多个子块分批迁移，降低单次迁移的阻塞时间；（2）实现迁移过程中的读写并发，通过 copy-on-write 机制在迁移期间仍允许对原数据的读访问；（3）针对 Stream、HyperLogLog 等特殊数据类型补充专用适配器。
>
> **5.2.4 Thread-Local Direct Cache 优化**
>
> 当前分配器对 64KB 以上大对象直接回退到 `numa_alloc_onnode()` 系统调用，每次分配均涉及内核态切换。未来可引入 Thread-Local Direct Cache 机制，在线程本地维护一个 16 槽位的 FIFO 环形缓冲区（`direct_cache_t`），缓存最近使用的 64KB–2MB 大对象分配块。该缓存完全运行在线程本地存储中，无锁无原子操作，可显著减少大对象分配的系统调用开销。
